# Substitute Control Classification Framework

ใช้ในการวิเคราะห์ SOP Gap Analysis — เมื่อพบว่า SOP ขาดการควบคุมที่ Master Context กำหนด 
ต้องประเมินว่ามีการควบคุมอื่นใน SOP ฉบับเดียวกัน หรือ SOP อื่นที่สามารถชดเชย (compensate) ได้หรือไม่

## 3 ระดับการจำแนก

| ระดับ | ความหมาย | ตัวอย่าง |
|---|---|---|
| 🔴 **ไม่มี** | ไม่มีการควบคุมใดๆ เลย — ความเสี่ยงไม่ถูกจัดการ | "ไม่มี SOP ใดกล่าวถึง Secret Management หรือ API Key Rotation" |
| ⚠️ **มีบางส่วน** | มีการควบคุมที่เกี่ยวข้องบางส่วนใน SOP นี้หรือ SOP อื่น — แต่ยังไม่เพียงพอหรือไม่ได้บูรณาการ | "SOP 07 (Procurement) มี PR/PO → ครอบคลุมการอนุมัติซื้อ แต่ยังขาดการตรวจสอบเกณฑ์ capitalization" |
| ✅ **มี** | มีการควบคุมอื่นที่สามารถชดเชยได้อย่างเพียงพอ — ไม่จำเป็นต้องเพิ่ม | "SOP 09 (Sales) มี Contract Risk Review → ครอบคลุมการตรวจสอบสัญญาก่อนลงนามแล้ว" |

## หลักการวิเคราะห์

1. **ตรวจสอบภายใน SOP เดียวก่อน** — SOP มีขั้นตอนอื่นที่ครอบคลุมบางส่วนหรือไม่
2. **ตรวจสอบข้าม SOP** — มี SOP อื่นที่ทำหน้าที่ทดแทนได้หรือไม่
3. **ระบุให้ชัดเจน** — ถ้า "มีบางส่วน" ต้องระบุว่า SOP ไหน, ครอบคลุมอะไร, ยังขาดอะไร
4. **ถ้า "ไม่มี" จริงๆ** — ต้องเป็น gap ที่ไม่มี SOP ใดครอบคลุมเลย (เช่น Secret Management ในบริษัทที่ไม่มี IT Security SOP)

## รูปแบบการเขียน

```
⚠️ มีบางส่วน — SOP 07 (Procurement) มีกระบวนการขอซื้อ (PR/PO) ที่ต้องผ่านการอนุมัติตาม Approval
Matrix ซึ่งครอบคลุมการควบคุมการจัดซื้อในระดับหนึ่ง แต่ยังขาด (1) การตรวจสอบเกณฑ์การบันทึกเป็น
สินทรัพย์ถาวร (capitalization criteria) และ (2) การตรวจสอบ Annual Fixed Asset Budget
```

องค์ประกอบ:
- สัญลักษณ์ระดับ (🔴/⚠️/✅)
- SOP ต้นทางที่ให้การควบคุมทดแทน
- กระบวนการที่เกี่ยวข้องใน SOP นั้น
- สิ่งที่ครอบคลุมแล้ว
- สิ่งที่ยังขาด (เจาะจง)
